# Agent Onboarding Guide

Welcome to Fable. This guide orients autonomous/LLM-based assistants so they can work safely and productively inside the repo.

## Repo Snapshot

- **What**: Design-system workbench shipped as a reusable Vite plugin (`fable-workbench`). Built with Lit 3 + Vite 7.
- **Monorepo**: npm workspaces with two packages:
  - `packages/fable/` -- core library + Vite plugin (npm name: `fable-workbench`)
  - `packages/demo/` -- example consumer app (deployed to GitHub Pages)
- **Entry Points**:
  - `packages/fable/src/plugin.js` -- Vite plugin (`fable()`)
  - `packages/fable/src/index.js` -- app bootstrap (imports UI + app shell, exports `define`)
  - `packages/fable/src/define.js` -- component registration API
  - `packages/fable/src/app.js` -- Lit orchestration of sidebar + main content
  - `packages/fable/src/store/` -- shared state + selectors
  - `packages/fable/ui/` -- built-in UI primitives
  - `packages/demo/vite.config.js` -- consumer Vite config example
  - `packages/demo/src/main.js` -- consumer entry point example
- **Docs & Specs**: `docs/spec.md` (overview) and `docs/specs/*.md` for feature deep dives. Architecture decisions in `docs/decisions/`.

## How Consumers Use Fable

1. Install `fable-workbench` and `vite`
2. Add `fable()` plugin to `vite.config.js` (import from `fable-workbench/plugin`)
3. Import `fable-workbench/style.css` and `fable-workbench` in their entry JS
4. Register components with `define(tag, Class)` -- stories, args, and metadata come from static class fields

See `packages/demo/` for a minimal working example.

## Development Scripts

All scripts run from the repo root and delegate to `packages/demo`:

- `npm run dev` -- Vite dev server with HMR at `http://localhost:3000`
- `npm run build` -- Vite static export to `packages/demo/dist/`

## Story Authoring Pattern

Components declare stories via static class fields, then register with `define()`:

```js
import { define } from "fable-workbench";

class MyComponent extends LitElement {
  static title = "My Component";
  static args = { label: "Hello" };
  static stories = {
    Default: (args) => html`<my-component>${args.label}</my-component>`,
  };
  // ...
}

define("my-component", MyComponent);
```

## Architecture Highlights

- **Two-column layout**: `fable-story-navigator` sidebar + `fable-story-preview` main content.
- **Global store**: module-level state with helper functions; `"state-changed"` events on `window`. No Redux/MobX.
- **URLPattern router**: base path lazily resolved from `window.__FABLE_BASE_PATH__` (set by `app.js` from Vite's `import.meta.env.BASE_URL`).
- **Vite plugin**: sets up resolve aliases mapping `fable-workbench` imports to the library source.

## File Conventions

- ES modules throughout, no bundler-specific APIs.
- Biome for linting/formatting (double quotes, semicolons, 2-space indent, 100-char width).
- Keep component classes prefix-free for UI primitives, `fable-` prefix for app shell components.

## Agent Safety Checklist

1. **Read Existing Changes**: worktree may contain user edits; never revert unrelated modifications.
2. **Respect Monorepo Layout**: changes to the core library go in `packages/fable/`, consumer-facing changes in `packages/demo/`.
3. **Greenfield Mindset**: ADR 0002 establishes no legacy/backward compatibility. Feel free to break old URLs/meta schemas -- just keep current code working and document changes.
4. **Docs First**: update specs/ADRs alongside code when introducing new behaviors.
5. **Testing**: verify via `npm run dev` (HMR preserves router state). Document what was tested in PR descriptions.
6. **Files to Avoid**: do not edit `packages/demo/dist/` directly; it is generated by `npm run build`.
